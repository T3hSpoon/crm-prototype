<objective>
Add a "Deal Terms" inspect/edit mechanism for existing deals: a new `DealTermsDialog` component (structurally mirroring `WonContractTermsDialog`) lets a user view and edit the 7 deal-terms fields (Prorata, Grace Period, Contract Term, Frequency, Currency, Customer Type, Confidence Level) captured at deal creation, reachable via a new "Deal Terms" button on `LineItemsTable`'s document-actions row — available for every deal, including Lost ones.

This plan is one small vertical slice split into two tasks for review clarity: Task 1 proves the harder coupling (schema reuse, store `Pick`-type widening, the dialog's prorata boolean<->"yes"/"no" conversion and pre-fill/error-state contract) end-to-end at the type/component level. Task 2 is the expansion that wires a real trigger into `LineItemsTable`, making the capability reachable by a user and restructuring the bottom row so the new button sits opposite the existing document controls without disturbing them.

Purpose: today the 7 deal-terms fields are set once at creation (`AddDealDialog` step 2) and then have no way to be inspected or corrected afterward. This closes that gap without inventing new validation or option values — it reuses the exact schema and Select option lists the Add Deal wizard already defines.

Output: `deal-terms-schema.ts` (new), `DealTermsDialog.tsx` (new), `pipelineStore.ts`'s `updateDeal` Pick type widened, `LineItemsTable.tsx`'s bottom row restructured with a right-aligned "Deal Terms" trigger.
</objective>
