### Page layout

Mirrors `ForecastPage.tsx`'s container/heading convention exactly:

**Visual focal point / reading order:** Row 1 (`UnitTargetGauge` + `TargetVsActualChart`) is the primary focal pair — it answers "are we hitting the unit target" at a glance and should draw the eye first (top position, largest single numeric value on the page via the Display-tier gauge reading). Rows 2-3 (`OwnerLeaderboard` + `ConversionFunnelChart`, then `ClosedByOwnerChart`) are secondary, supporting drill-down context read in top-to-bottom, left-to-right order after Row 1.

```
<div className="mx-auto flex w-[95%] flex-col gap-6 px-6 py-8">
  <h1 className="font-heading text-lg font-semibold">Dashboard</h1>

  <!-- Row 1: unit-target pair -->
  <div className="grid grid-cols-1 gap-4 lg:grid-cols-2">
    <UnitTargetGauge />        <!-- DASH-01 -->
    <TargetVsActualChart />    <!-- DASH-02 -->
  </div>

  <!-- Row 2: people + process pair -->
  <div className="grid grid-cols-1 gap-4 lg:grid-cols-2">
    <OwnerLeaderboard />        <!-- DASH-03 -->
    <ConversionFunnelChart />   <!-- DASH-04 -->
  </div>

  <!-- Row 3: full-width closed-deal history -->
  <div className="grid grid-cols-1 gap-4">
    <ClosedByOwnerChart />      <!-- DASH-05 -->
  </div>
</div>
```

**Chart container heights** (RESEARCH.md Pitfall 6 — never size a `ResponsiveContainer` to just the plot area, exclude nothing needed for axis/legend bands):

| Component | `ResponsiveContainer height` | Reason |
|-----------|-------------------------------|--------|
| `UnitTargetGauge` | 220px | Semicircle meter, no x-axis/legend band to reserve room for |
| `TargetVsActualChart` | 300px | 12 monthly x-axis labels + legend (Actual/Target) |
| `ConversionFunnelChart` | 320px | 5 funnel stages + right-side `LabelList` |
| `ClosedByOwnerChart` | 300px | 12 monthly x-axis labels + 5-entry owner legend |
| `OwnerLeaderboard` | n/a (not a Recharts chart — a Card with up to 5 flex rows) | — |

**Month-axis tick format:** `date-fns` `format(d, "MMM yyyy")` (e.g. "Jan 2026") for DASH-02/DASH-05 — matches RESEARCH.md Pattern 2/5 exactly, short enough to never need `TruncatedTick`.

## Spacing Scale

Declared values (must be multiples of 4) — reuses the project's existing scale verbatim, no new values introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/label gaps within a widget header |
| sm | 8px | Compact spacing (`gap-2`, chart legend item gaps) |
| md | 16px | Card padding (`p-4`, matches `StatTile`/`LostBreakdownChart`), grid gaps (`gap-4`) |
| lg | 24px | Page-level vertical rhythm between widget rows (`gap-6`, matches `ForecastPage`) |
| xl | 32px | Not used this phase (no widget needs a break this large) |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

**Exceptions:** none for Phase 6. No spacing value outside the 8-point scale above is introduced by this phase's 5 widgets.

**Known pre-existing issue (not a Phase 6 exception, not to be reused):** `GroupSection.tsx`'s existing count-badge uses `rounded-full bg-background/80 px-2 py-0.5 text-xs font-medium` — its `py-0.5` (2px vertical) is a pre-existing, off-grid value from Phase 1-era code, called out here only so it is not mistaken for an approved pattern. If `OwnerLeaderboard` needs a rank or count badge, do not copy `py-0.5`; use a 4px-conforming badge instead, e.g. `rounded-full bg-background/80 px-2 py-1 text-xs font-medium leading-none` (4px vertical padding, `leading-none` keeps the rendered badge height visually equivalent to the old 2px version despite the larger padding value).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | 600 semibold | 1.5 |
| Body | 14px (`text-sm`) | 400 regular (paragraph/caption/empty-state copy); 600 semibold (widget Card titles) — see note | 1.5 |
| Heading | 18px (`text-lg`, `font-heading`) | 600 semibold | 1.2 |
| Display | 24px (`text-2xl`) | 600 semibold, `tabular-nums` | 1.2 |

**Note (dual-weight Body, by established convention, not a new rule):** 14px is used at 400/regular for prose (e.g. empty-state sentences: `text-sm text-muted-foreground`) and at 600/semibold for widget Card titles (`<h3 className="text-sm font-semibold">`, exact `LostBreakdownChart.tsx` pattern). This is the only role where weight varies by usage in this phase; Label/Heading/Display are single-weight throughout.

**Usage map for this phase's widgets:**
- Page `<h1>` — Heading (18px/600, `font-heading`)
- Widget Card `<h3>` title (e.g. "Unit Sales Target", "Owner Leaderboard") — Body/semibold (14px/600)
- Axis labels, legend text, stat captions — Label (12px/600) or Body/regular (14px/400) matching `LostBreakdownChart`'s existing `fill: "#898781", fontSize: 12` tick styling
- Gauge/leaderboard large numeric values (units, currency) — Display (24px/600, `tabular-nums`)

## Color

### 60/30/10 (UI chrome — unchanged from existing app-wide tokens)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` — `oklch(1 0 0)` light / `oklch(0.145 0 0)` dark | Page background |
| Secondary (30%) | `var(--card)` / `var(--muted)` — `oklch(1 0 0)`/`oklch(0.97 0 0)` light, `oklch(0.205 0 0)`/`oklch(0.269 0 0)` dark | Widget Card surfaces, chart-grid background |
| Accent (10%) | `var(--chart-gauge-fill)` — `#2a78d6` light / `#3987e5` dark | Reserved for: DASH-01 gauge fill arc, DASH-02 "Actual" bar series only |
| Destructive | `var(--destructive)` | Not used in Phase 6 — no destructive actions exist (read-only dashboard) |

**Accent reserved for:** the gauge's filled arc (`UnitTargetGauge`) and the "Actual" bar in `TargetVsActualChart` — nowhere else. Do not reuse `--chart-gauge-fill` for any other widget's primary mark (Leaderboard bars, funnel stages, and stacked-bar owner segments each use their own palette below, to avoid implying a false relationship between unrelated widgets).

### Chart-specific palette (new tokens — add to `src/index.css`, both `:root` and `.dark`, following the existing `--chart-lost-bar`/`--chart-lost-grid` convention exactly)

| Token | Light | Dark | Used by |
|-------|-------|------|---------|
| `--chart-gauge-fill` | `#2a78d6` | `#3987e5` | DASH-01 gauge fill, DASH-02 "Actual" bar |
| `--chart-gauge-track` | `#cde2fb` | `#184f95` | DASH-01 gauge unfilled background track |
| `--chart-owner-1` | `#2a78d6` | `#3987e5` | DASH-05 stacked bar — Owner Roster[0] |
| `--chart-owner-2` | `#eb6834` | `#d95926` | DASH-05 stacked bar — Owner Roster[1] |
| `--chart-owner-3` | `#1baf7a` | `#199e70` | DASH-05 stacked bar — Owner Roster[2] |
| `--chart-owner-4` | `#eda100` | `#c98500` | DASH-05 stacked bar — Owner Roster[3] |
| `--chart-owner-5` | `#e87ba4` | `#d55181` | DASH-05 stacked bar — Owner Roster[4] |
| `--chart-funnel-1..5` | `#86b6ef` → `#104281` (5-step ramp) | `#9ec5f4` → `#184f95` (5-step ramp) | DASH-04 funnel stages, Prospect→Won, lightest→darkest |

All values are copied verbatim from `06-RESEARCH.md` §Architecture Patterns (validated this session via the dataviz skill's `validate_palette.js`, both light/dark PASS for CVD separation and contrast). **Locked decision for this UI-SPEC:** the funnel uses the validated single-hue ordinal ramp (`--chart-funnel-1..5`), not `GROUP_META`'s per-stage Tailwind hues — `GROUP_META` is not exported from `GroupSection.tsx` and coupling the Dashboard to Pipeline internals is unnecessary when a pre-validated alternative already exists (RESEARCH.md flagged this as a discretion point; resolved here so planning/execution has one answer, not two options).

Owner-color assignment is **positional and fixed**: color index = the owner's index in the fixed 5-name `OWNER_ROSTER` array (D-01), never a runtime-sorted array's index — so a given rep's color never changes when the Leaderboard re-sorts (RESEARCH.md Anti-Patterns).

**Leaderboard bars/rows:** single hue only (`var(--chart-gauge-fill)` or plain `var(--muted-foreground)`/`var(--foreground)` text, no per-owner color) — DASH-03 is a magnitude comparison of one series, not an identity display; per-owner rainbow coloring here would misstate the chart's job (RESEARCH.md Anti-Patterns).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None.** Phase 6 is a read-only dashboard — no forms, no write actions, mirroring `ForecastPage.tsx`'s established "no write actions" convention (Forecast's D-03). No CTA button exists anywhere on this tab. |
| Empty state — DASH-01 Gauge | "No Won deals yet — the gauge fills in once deals close." (centered, `text-sm text-muted-foreground`, replaces the `RadialBarChart` entirely, same placement pattern as `LostBreakdownChart`'s empty branch) |
| Empty state — DASH-02 Target vs. Actual | "No closed-deal history yet — this chart fills in as Won deals accumulate month over month." |
| Empty state — DASH-03 Leaderboard | "No Won deals yet — the leaderboard fills in once deals close." |
| Empty state — DASH-04 Conversion Funnel | "No deals in the pipeline yet." (only reachable if the store's `deals` array is empty, e.g. before seed load completes) |
| Empty state — DASH-05 Stacked Bar | "No closed deals yet — this chart fills in as deals are won or lost." |
| Error state | **Not applicable this phase.** No network/fetch surface exists — all 5 widgets are pure synchronous computations over already-loaded in-memory store state (RESEARCH.md Security Domain: "no new form/input... no network calls"). No error/retry copy needed. If a future API-backed phase adds fetch failures here, that phase must define its own error copy — none is inherited from Pipeline/Forecast since neither has established one yet. |
| Destructive confirmation | **Not applicable.** No destructive actions exist in this phase (read-only). |

**Style rule for all 5 empty-state strings above:** follow `LostBreakdownChart.tsx`'s exact voice — "No {noun} yet — {what causes it to fill in}." Rendered as `<p className="p-8 text-center text-sm text-muted-foreground">`, replacing the chart/list entirely (not overlaid on an empty chart frame).

## UI Considerations

Applicable state considerations resolved: 7 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | All 5 widgets (gauge=media, chart/leaderboard/funnel/stacked-bar=list-collection) | ✅ covered | Each widget replaces its chart/list with the exact `LostBreakdownChart.tsx` empty-state pattern; copy is widget-specific — see Copywriting Contract rows above |
| loading | All 5 widgets | ✅ covered | Dismissed — no async load exists on this tab; `DashboardPage` reads `usePipelineStore((s) => s.deals)` synchronously post-mount (data already loaded once at `App` mount via `store.load()`), identical to `ForecastPage`'s zero-loading-state convention |
| error | All 5 widgets | ✅ covered | Dismissed — no network/fetch surface this phase (RESEARCH.md Security Domain confirms no new input/network surface); see Copywriting Contract "Error state" row |
| populated | All 5 widgets | ✅ covered | Seed volume raised to ~150 deals (RESEARCH.md A6) so every widget renders a credible non-trivial dataset; each of the 5 roster owners verified to have ≥1 Won deal (RESEARCH.md Pitfall 3 spot-check requirement) |
| partial | DASH-02 monthly buckets, DASH-05 stacked bar, DASH-03 leaderboard | 🧪 backstop | A sparse month (0 units/deals) or an owner with 0 Won deals must render as a real zero bar/row, never a silently-skipped category — `computeMonthlyWonUnits`/`computeClosedByOwnerPerMonth` pre-seed all 12 months and all 5 roster owners at 0 before accumulating (RESEARCH.md Pattern 2/5 code). Needs an explicit test asserting a zero-value bucket still appears in the output array. |
| overflow | DASH-05 legend/tick labels, DASH-03 leaderboard owner names | ✅ covered | Fixed roster names (D-01, e.g. "Elena Torres") are ≤14 chars — within `LostBreakdownChart`'s existing `TruncatedTick` 14-char threshold; reuse that component verbatim for any owner-labeled axis tick. Recharts' default `<Legend>` wraps rather than clips a 5-entry legend at typical widths. |
| zero-one-many | DASH-03 leaderboard, DASH-04 funnel | ✅ covered | Leaderboard always lists the fixed 5-name `OWNER_ROSTER` sorted by Won value — bounded 0-5 rows, never unbounded; funnel always renders exactly 5 fixed stages (Prospect→Won) regardless of deal count (`computeConversionFunnel`'s fixed `stages` array, RESEARCH.md Pattern 4) |
| long-text | DASH-03 leaderboard owner names, DASH-05 legend owner names | ✅ covered | Fixed roster names are short (2 words, ≤14 chars) by construction — no long-text risk from the roster itself; if the roster is ever changed to longer names, apply `TruncatedTick`-style truncation as the fallback |
