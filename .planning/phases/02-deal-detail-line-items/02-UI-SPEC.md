## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding inside editable cells |
| sm | 8px | Compact element spacing (line-item row internal gaps) |
| md | 16px | Default element spacing (drawer section gaps, `SheetContent` padding) |
| lg | 24px | Section padding (drawer outer padding on `sm:` and up) |
| xl | 32px | Layout gaps (not expected to be needed this phase) |
| 2xl | 48px | Major section breaks (not expected to be needed this phase) |
| 3xl | 64px | Page-level spacing (unchanged from Phase 1's `PipelineBoard` `py-8`) |

**Exceptions (inherited from Phase 1 / shadcn primitives — do not "fix" these this phase):**
- shadcn-generated primitives (`Button`, `Input`, `Field`) use intermediate Tailwind spacing values (`px-2.5`=10px, `gap-1.5`=6px, `p-2.5`=10px) baked into their variant classes. These are pre-existing, out-of-scope-to-change component internals, not new Phase 2 spacing decisions.
- Icon-only buttons in this project use `size-7`/`size-8` (28px/32px) touch targets (`Button` `icon-sm`/`icon` sizes), not a 44px minimum — this is a desktop-oriented prototype (no mobile breakpoint requirement in REQUIREMENTS.md), consistent with Phase 1's existing icon buttons (dialog close button). The new line-item row "remove" button follows this same `icon-sm` convention.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 regular | 1.5 |
| Label | 12px (`text-xs`) | 600 semibold | 1.2 |
| Heading | 16px (`text-base`) | 600 semibold | 1.2 |
| Display | 20px (`text-xl`) | 600 semibold | 1.2 |

**Usage mapping for this phase's new UI:**
- Body (14px/400/1.5): line-item cell values, editable-cell display text, drawer field values, table cell text — matches `DealTable`'s existing `text-sm` body copy.
- Label (12px/600/1.2): field labels inside the drawer (`FieldLabel`), line-items table column headers, the "Reset to sum" microcopy — slightly bolder than Phase 1's inherited `FieldLabel` (`text-sm font-medium`) by deliberate choice, to visually distinguish "label" from "body" now that the drawer packs more label/value pairs into a narrower column than the pipeline table did.
- Heading (16px/600/1.2): `SheetTitle` (deal name) and the "Line Items" section heading inside the drawer.
- Display (20px/600/1.2): the deal's Value field when rendered in its non-editing (display) state — this is the one number in the drawer that should read as the most important figure on the panel.

**Weight discipline:** Only 400 and 600 are used in new Phase 2 code. Phase 1's shipped primitives (`Button`, `DialogTitle`, `FieldTitle`) use `font-medium` (500) internally — an inherited exception from before this contract existed, not to be propagated into any new Phase 2 component.

## Color

This project's theme is a grayscale-first `neutral` shadcn base — there is no single saturated "accent hue" the way a branded product would have one. Visual identity comes from two places: (1) the neutral surface/border scale below, and (2) Phase 1's per-pipeline-stage hue palette (`GroupSection.tsx`'s indigo/amber/cyan/emerald/rose tints), which is out of scope to change or extend this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` light / `oklch(0.145 0 0)` dark) | Drawer (`SheetContent`) surface, page background |
| Secondary (30%) | `--muted` / `--card` / `--border` (`oklch(0.97 0 0)` light / `oklch(0.269 0 0)` dark) | Line-items table header row, table/cell borders, drawer section dividers (`Separator`), non-editing cell hover background |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)` light / `oklch(0.922 0 0)` dark) | See "Accent reserved for" below |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)` light / `oklch(0.704 0.191 22.216)` dark) | Remove-line-item icon hover state text color; `aria-invalid` field border/ring states (inherited global pattern) |

**Accent reserved for:** `PipelineBoard`'s existing "Add Deal" button only (unchanged from Phase 1). Phase 2 introduces **no new primary/accent-colored element**. Specifically:
- "Add Line Item" uses `Button variant="outline"`, not the default/primary variant — deliberately, so it never visually competes with the board's "Add Deal" button when both are on screen (drawer open over the board).
- The "Reset to sum" affordance uses `Button variant="outline" size="sm"` with a `RotateCcw` icon — a neutral, low-emphasis action, not a colored badge or accent-colored button. This avoids inventing a new semantic color for a niche affordance.
- Editable cells in their editing state use the existing `Input`/focus-ring styling (`--ring`) already established project-wide — no new accent treatment.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Add Line Item" (button inside the drawer's line-items section; not page-level — the board's "Add Deal" primary CTA is unchanged from Phase 1) |
| Empty state heading | "No line items yet." |
| Empty state body | "Add a line item to start building this deal's value automatically." |
| Error state | "Update failed — your change wasn't saved. Try again." (inline, non-blocking banner within the drawer; the field/row reverts to its last committed value, per Pitfall 5's carried-forward gap) |
| Destructive confirmation | Remove line item: no confirmation dialog — a single click removes the row immediately (low-stakes, reversible by clicking "Add Line Item" again; consistent with REQUIREMENTS.md's "no full spreadsheet-grade editing" scope boundary). This is distinct from Phase 3's "mark deal Lost" flow, which *will* require a reason gate — not the same interaction, not to be confused. |
| Reset-to-sum affordance label | "Reset to sum ({currency-formatted computed total})" — e.g. "Reset to sum ($12,400)" |
| Field-edit save feedback | None — fields auto-commit silently on blur/Enter (per D-03's field-level auto-commit model). No toast, no "Saved" indicator. Only a failed commit produces visible feedback (see Error state row above). |
| Drawer close | "Close" (icon-only `X` button, `sr-only` text "Close") — same pattern as `DialogContent`'s existing close button; `sheet.tsx` will follow the identical convention. |

## Assumptions Made (Runtime Note — auto mode, no user confirmation this round)

Per the orchestrator's `--auto` instruction, the following judgment calls were made without stopping for user sign-off. All are consistent with 02-CONTEXT.md's stated defaults and 02-RESEARCH.md's recommendations; flagged here for audit and easy revisit at UAT:

1. **Sheet side and width:** `side="right"`, `className="w-full sm:max-w-lg overflow-y-auto"` (research's recommended default). Not explicitly locked by D-01 beyond "side drawer."
2. **"Add Line Item" and "Reset to sum" both use `variant="outline"`, not the primary/default button variant** — to avoid two competing accent-colored CTAs on screen at once (board's "Add Deal" + drawer's own buttons). This is a new interpretation of the existing neutral-first color contract, not previously codified anywhere in Phase 1.
3. **Label typography bumped to 600 semibold / 12px**, slightly bolder than Phase 1's inherited `FieldLabel` (`text-sm font-medium`) — deliberate for the denser drawer layout. Does not require changing `field.tsx` itself; only new Phase 2 label usage should follow this row of the Typography table.
4. **No confirmation dialog on line-item removal** — one-click remove. Distinguished explicitly from Phase 3's lost-reason gate so implementers don't conflate the two "removal-like" flows.
5. **DEAL-05's computed-until-touched override behavior (carried from 02-RESEARCH.md Pattern 4 / Open Question 1)** is treated as locked for this UI-SPEC's purposes (comparison-based, no `hasManualOverride` field) — this remains the single lowest-confidence design call in the phase per research; the planner/executor should still feel free to revisit with the user if it doesn't sit right during planning or UAT.
6. **Error-state copy and inline-banner treatment for failed commits** is a new decision not present in any prior phase artifact (Phase 1 has no UI for a failed `moveStage`/`addDeal` call today) — introduced here to close the carried-forward Pitfall 5 gap for this phase's new write actions specifically. Phase 1's existing gap remains open and out of scope to fix retroactively.
