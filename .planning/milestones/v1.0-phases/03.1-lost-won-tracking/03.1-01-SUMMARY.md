# Phase 03.1 Plan 01: Lost-Reason Gate Summary

**Popover-gated Lost-reason capture via a new `moveToLost` atomic store action — picking "Lost" in any row's StageSelect now requires a category before the deal moves, with an optional note and inline failure recovery.**

## Performance
- **Duration:** ~25min
- **Started:** 2026-09-11 (session start)
- **Completed:** 2026-09-11T10:42:42Z
- **Tasks:** 2
- **Files modified:** 7 (4 created, 3 modified)

## Accomplishments
- Hand-wrote `src/components/ui/popover.tsx` (Popover/PopoverAnchor/PopoverContent) from the already-installed `@radix-ui/react-popover` transitive dependency, mirroring `dialog.tsx`'s exact import/data-slot convention.
- Added `lostReasonSchema`/`LostReasonFormValues` (the 5 fixed Reason categories per D-03, plus optional free-text note).
- Built `LostReasonPopover.tsx` as form-content-only (no owned `Popover.Root`) so the parent `StageSelect`'s Popover alone governs open/close — keeping submit-close and Escape/click-away-dismiss on two separate, never-overlapping code paths (D-04).
- Added the atomic `moveToLost` store action to `pipelineStore.ts`, mirroring `moveStage`'s single `dealsRepository.update()` call shape exactly — no two-write race possible.
- Rewired `StageSelect.tsx`'s `handleValueChange` to intercept the "lost" selection via local `pendingGroup` state instead of calling `moveStage` directly; every other group selection is unchanged.
- Added `src/components/ui/textarea.tsx` and wired a "Note (optional)" field into the popover.
- Added try/catch + log + rethrow to `moveToLost` (mirroring `updateDeal`'s existing pattern) and a matching catch block in `LostReasonPopover.tsx` that shows "Couldn't save — try again." inline, keeps the popover open, and preserves the user's selections.
- Updated `deal.ts`'s `lostReason` doc comment to reflect its now-active use.

- No submit-in-flight spinner / double-submit guard added — carries forward the same documented backstop gap from the Add Deal wizard (plan's own `must_haves.truths` backstop item).
