# Phase 3.1 — UI Design Contract

> Visual and interaction contract for Lost & Won Tracking (LOST-01, LOST-02, PIPE-03, WON-01).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker. Extends, and must stay visually
> consistent with, Phase 1–3's shipped pipeline board and Add Deal wizard — conventions below are
> carried forward from `02-UI-SPEC.md`/`03-UI-SPEC.md` (both approved) and reverse-derived from
> the actual shipped code (`GroupSection.tsx`, `StageSelect.tsx`, `AddDealDialog.tsx`,
> `DealTable.tsx`, `src/components/ui/{dialog,field,input,select,button}.tsx`).

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present, no gate needed) |
| Preset | `radix-nova` style, `neutral` base color, CSS-variable theming, no `tailwind.config.js` (Tailwind v4 CSS-first, `src/index.css`) |
| Component library | Radix UI primitives (via shadcn, unified `radix-ui` package) |
| Icon library | lucide-react |
| Font | Geist Variable (`@fontsource-variable/geist`), aliased to `font-sans`/`font-heading` — no separate display typeface in this project |

**New this phase:** `src/components/ui/popover.tsx` must be hand-written (or CLI-generated then diffed) before `LostReasonPopover` is built — 03.1-RESEARCH.md confirms `@radix-ui/react-popover@1.1.23` is already present in `node_modules` as a transitive dependency of the installed `radix-ui` meta-package, so this is **not** a new npm install, and it sources from the shadcn **official** registry (not third-party) — no registry-safety review required. Structure it as a direct sibling of `dialog.tsx` (`Root`/`Trigger`/`Portal`/`Content`/`Close`/`Anchor`, `import { Popover as PopoverPrimitive } from "radix-ui"`, `cn` from the `"cn"` package) — do not trust `npx shadcn@latest add popover`'s raw output verbatim against this repo's custom `"radix-nova"` style without diffing it against `dialog.tsx`'s import convention first.

No other new shadcn primitives are needed: the Won contract-terms modal reuses `dialog`, `field`, `input`, `label`, `select`, `button` exactly as `AddDealDialog.tsx` already does.

## Visual Hierarchy / Focal Point

| Surface | Focal Point |
|---------|-------------|
| Lost-reason popover | The reason `Select` (category) is the focal point — it is the first and only required control, sits directly under a one-line prompt ("Why was this deal lost?"), and the "Mark as Lost" submit button (disabled until a category is chosen) is the sole accent-colored element, anchoring the eye from prompt → select → accent button in a single vertical line. The optional note field is visually secondary (plain textarea, no accent border) so it never competes with the required category select. |
| Won contract-terms dialog | The "Confirm Won" button is the focal point, as the terminal action of the only path that completes WON-01's gate — it is the single accent-colored control competing with 4 editable fields + 1 read-only confirmation field above it, matching Phase 3's established "one accent-colored control per screen" rule from `03-UI-SPEC.md`. The read-only Final Contract Value field is visually de-emphasized (muted background, no input border) so it reads as a confirmation, not another editable input competing for attention. |
| "Contracts" (Won) group section | Unchanged from every other `GroupSection` — the group header's summed value (top-right, `text-sm font-semibold`) is the section's focal point, consistent with Prospect/Lead/Opportunity/Deal/Lost. No new focal-point pattern is introduced for this group. |

## Color

This project's theme is a grayscale-first `neutral` shadcn base — visual identity comes from (1) the neutral surface/border scale below, and (2) the per-pipeline-group hue palette in `GroupSection.tsx`, which this phase extends by exactly one new entry.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` light) | Popover surface (`PopoverContent`), dialog surface (`DialogContent`), page background |
| Secondary (30%) | `--muted` / `--border` (`oklch(0.97 0 0)` light) | Popover/dialog borders, read-only Final Contract Value field background, `Won` group table header row (inherited, unchanged) |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)` light) | See "Accent reserved for" below |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)` light) | Field-level validation error state only (invalid border/ring on the reason `Select`, the Won dialog's required date/text fields, `FieldError` text) |

**Accent reserved for:** the popover's "Mark as Lost" submit button, the Won dialog's "Confirm Won" button, and focus-visible rings (`--ring`) on the currently-focused field in either surface. Every other control (popover's implicit dismiss via Escape/click-away — no button exists for it per D-04; the Won dialog's "Cancel" button) stays neutral/`variant="outline"`, so the single primary path in each surface (submit) remains visually distinct — same rule `03-UI-SPEC.md` established for Next/Create Deal vs. Back/Cancel.

**New per-group hue (GROUP_META extension, `GroupSection.tsx`):**

| Group | Label | Icon | Accent border | Tint |
|-------|-------|------|----------------|------|
| `deal` (existing, relabeled) | "Deal" (was "Deal / Won" — the "/Won" suffix must be dropped now that Won is its own distinct group, per PIPE-03) | `Briefcase` (was `Trophy` — `Handshake` is already `opportunity`'s icon, so `Briefcase` is the distinct replacement for the active/funnel Deal stage) | `border-l-emerald-400` (unchanged) | `bg-emerald-50/60 dark:bg-emerald-950/20` (unchanged) |
| `won` (new) | "Contracts" — reinforces PIPE-03's "contracts made so far" framing directly in the group label | `Trophy` (moves here from `deal`) | `border-l-yellow-400` (new hue — distinct from `lead`'s existing `amber-400`) | `bg-yellow-50/60 dark:bg-yellow-950/20` |

These per-group tints are decorative section identity (matching Phase 1's original 5-hue system), not part of the 60/30/10 interactive accent — this distinction was already established in `02-UI-SPEC.md` and is unchanged.

## Assumptions Made (flagged for planner/UAT revisit)

These resolve 03.1-CONTEXT.md's explicitly time-boxed "Claude's Discretion" items and 03.1-RESEARCH.md's Assumptions Log (A2–A6) into a concrete visual/copy contract. All are consistent with research's recommended defaults; none are locked user decisions — revisit at plan time or UAT if something doesn't sit right, same posture prior phases' UI-SPECs took.

1. **No intermediate "confirm" screen before the Won terms form** (resolves 03.1-RESEARCH.md Open Question 1 / Assumption A5): selecting "Won" in `StageSelect` opens the dialog directly showing the contract-terms form — not a 2-step "confirm → terms" wizard. Mirrors D-01's precedent for Lost (picking "Lost" directly opens the reason popover, no confirm step).
2. **Final Contract Value is read-only, pre-filled from `Deal.value`, not independently editable** (resolves Assumption A2): treated as a confirmation of the deal's value at Won time, not a second, potentially-diverging figure. If a later phase needs an immutable historical snapshot distinct from `Deal.value` (which keeps auto-tracking line-item sums per DEAL-05 even after Won), this field's read-only treatment should be revisited.
3. **Payment Terms is a single required free-text field**, not a reuse of the existing `frequency` enum plus a separate structured net-terms field (resolves Assumption A3). Simpler form, one fewer question — at the cost of not being cleanly filterable if Phase 4's forecast page later wants to query by billing cadence specifically.
4. **Contract End Date pre-fills from `contractStartDate + contractTermMonths`** via `date-fns`'s `addMonths`, but remains a user-editable field, not a locked/computed display value (resolves Assumption A4) — guards against the two figures silently drifting apart while still letting the user override.
5. **`deal` group's icon changes from `Trophy` to `Briefcase`** (Trophy moves to the new `won` group) and its label drops the "/Won" suffix (resolves Assumption A6). Purely cosmetic — the lowest-risk assumption in this contract, a one-line fix if wrong.
6. **Lost-reason popover has no explicit Cancel button** — Escape/click-away (D-04) is the only dismiss path. If UAT feedback prefers an explicit button for discoverability, this is a low-risk addition, not a structural change.
