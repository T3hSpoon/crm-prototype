## Tests

### 1. Lost popover opens, disabled-state gate, and submit moves the deal
expected: A popover opens anchored to the dropdown with a Reason select, no category pre-selected, and "Mark as Lost" disabled until a category is chosen. Picking a category and submitting moves the deal into the Lost group.
result: pass

### 2. Lost popover Escape-dismiss reverts the dropdown
expected: Pressing Escape before submitting closes the popover; the dropdown still shows the deal's original stage (not moved). Also covers the "zero store actions on cancel" invariant — no automated test exercises this.
result: pass

### 3. Lost note persistence (with and without a note)
expected: Picking "Lost", choosing a category, typing a note, and submitting succeeds with the note preserved and concatenated into lostReason as "{category}: {note}"; a second deal with a category chosen and the note left blank also succeeds.
result: pass

### 4. Won dialog opens, auto-prefill, and submit moves the deal
expected: Picking "Won" opens the Mark Deal as Won dialog directly (no separate confirm screen) with 4 blank date/text fields plus a read-only Final Contract Value already showing the deal's current value. Filling Contract Start Date auto-fills Contract End Date to start + the deal's Contract Term (months), and remains editable. Filling the remaining fields and clicking "Confirm Won" moves the deal into the Contracts group with a distinct yellow-accented header.
result: pass

### 5. Won dialog Cancel is a no-op
expected: Reopening the Won dialog on another deal and clicking Cancel closes it with no group change. Also covers the "zero store actions on cancel" invariant — no automated test exercises this.
result: pass

### 6. Contracts group demoable on first load + empty-state copy
expected: Refreshing the app shows at least one deal already in the Contracts group with its Final Contract Value visible. A naturally-empty active-stage group still reads "No deals in this group yet.", not "No contracts yet."
result: pass
