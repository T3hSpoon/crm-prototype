**Additional finding carried from code review (03.1-REVIEW.md, CR-01), not a STRIDE-classified threat:** `moveToLost`/`moveToWon`/`moveStage` never clear the *opposing* terminal-state's fields when a deal transitions away from Lost/Won (stale `lostReason` persists after un-losing a deal; stale contract-term fields persist after un-winning one). This is a data-integrity bug, not a security threat in the STRIDE sense (no privilege boundary crossed, no untrusted input involved) — reachable only through the deal's own legitimate owner using the shipped UI. Tracked in `03.1-VERIFICATION.md` and accepted by the user at UAT (`03.1-UAT.md` test 8) as a deferred gap, flagged for resolution before Phase 4's forecast page consumes this data.
