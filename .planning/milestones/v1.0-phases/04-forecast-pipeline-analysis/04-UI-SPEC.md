## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present, detected not asked) |

**Existing installed shadcn components:** `button`, `dialog`, `field`, `input`, `label`, `select`, `separator`, `popover`, `textarea`.

**Visual hierarchy (Forecast page):** The stat tiles row (raw pipeline value / weighted value / win rate) is the primary visual anchor — it sits above the two charts, and its Display-size (24px/600) numerals are the largest text on the page, drawing the eye first. The two bar charts (lost-by-reason, lost-by-stage) are secondary, read left-to-right below the tiles. On the Pipeline page, the tab switcher + toolbar (search/filters/toggle-group) sits above the existing `PipelineBoard`, which remains the primary content the eye lands on after the controls.

**New shadcn components to install this phase** (all official registry, no third-party source — safety gate not applicable):

| Component | Used for |
|-----------|----------|
| `tabs` | Pipeline / Forecast top-level tab switch (D-01) |
| `toggle-group` | Group-visibility multi-select pills (D-06) — Radix `ToggleGroup` in `multiple` mode is a direct fit for "checkboxes/pills for Prospect/Lead/Opportunity/Deal/Won/Lost" |
| `card` | Stat tiles (raw pipeline value / weighted value / win rate) and each chart's container, for visual parity with `GroupSection`'s existing `rounded-xl border bg-card shadow-sm` shell |

Install via `npx shadcn add tabs toggle-group card` — official registry only, `shadcn view`/vetting gate not triggered (no third-party registry declared, per CONTEXT.md's silence on this and RESEARCH.md's own component inventory).

## Spacing Scale

Declared values (must be multiples of 4), matching the scale already in use across `PipelineBoard`/`GroupSection`/`DealTable`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, sort-arrow-to-label gap, chart bar corner radius |
| sm | 8px | Compact element spacing — toolbar control internal padding, toggle-group pill padding |
| md | 16px | Default element spacing — toolbar row gap, stat-tile internal padding, `GroupSection`/`Card` body padding (matches existing `p-3`→round up to `p-4` for new cards) |
| lg | 24px | Section padding — page-level `gap-6` between Forecast page sections (stat tiles / charts), matches `PipelineBoard`'s existing `gap-6` |
| xl | 32px | Layout gaps — space above/below the tab switcher |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- `GroupSection`'s count-badge vertical padding (`py-0.5` = 2px) is a **pre-existing exception** from Phase 1, carried forward unchanged — not introduced by this phase.
- All **new** Phase 4 spacing (toolbar, tabs, toggle-group, stat tiles, charts) must stay on the 4px grid — no new sub-4px exceptions.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`) | 600 (semibold) | 1.2 |
| Heading | 18px (`text-lg`) | 600 (semibold) | 1.2 |
| Display | 24px (`text-2xl`) | 600 (semibold) | 1.15 |

Usage mapping for this phase's new UI:
- **Body** (14px/400): table cell text (unchanged), filter-input text, chart tooltip content, toolbar search input text.
- **Label** (12px/600): toggle-group pill labels, chart axis tick labels and legend, sort-column arrow indicator, stat-tile caption ("Raw Pipeline Value", "Weighted Value", "Win Rate").
- **Heading** (18px/600): tab labels ("Pipeline" / "Forecast"), matches the existing page `<h1>` (`font-heading text-lg font-semibold`, unchanged).
- **Display** (24px/600): the large number inside each stat tile (e.g. `$482,000`, `61%`) — the only new size introduced this phase.

Only **2 weights** exist project-wide going forward: 400 (regular) and 600 (semibold). Note: `GroupSection`'s existing count badge and `DealTable`'s existing header row use `font-medium` (500) from Phase 1 — a pre-existing, unaudited third weight. Do not extend `font-medium` to any new Phase 4 component; new UI uses only 400/600.

## Color

This project's theme is CSS-variable-driven (oklch, shadcn `neutral` base) — values below are the token, not a fixed hex, per `src/index.css`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)`, white) | Page background, table body rows, chart canvas background |
| Secondary (30%) | `--card` / `--muted` (`oklch(0.97 0 0)`, near-white gray) | Stat-tile and chart `Card` surfaces, table header row background, toolbar bar background, toggle-group unselected pill background |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)`, near-black in light mode) | Reserved for: the active tab's label + underline indicator, the active sort column's header text + arrow icon, the selected state of a toggle-group pill, and the single-series fill on both bar charts (see Chart Color below) |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)`, red) | No new destructive actions this phase (search/filter/sort/tabs/charts are all non-destructive, instantly-reversible view operations) — token is reserved as-is, unused by any new Phase 4 component |

Accent reserved for: active tab indicator, active sort-column header + arrow, selected toggle-group pill, single-series bar-chart fill. Never applied to static/inactive UI (unselected pills, unsorted headers, secondary text) — consistent with the 10%-of-surface intent.

**Existing per-group palette (unaffected, do not reuse for charts):** `GroupSection.tsx`'s `GROUP_META` (indigo/amber/cyan/emerald/yellow/rose) is a separate, already-established multi-hue system that identifies pipeline *stages* on the board. It is out of scope for this phase's charts — see Chart Color below for why the lost-breakdown charts use a single accent hue instead of borrowing this palette.

**Chart color (Recharts bar charts, FCST-02):** Both `LostBreakdownChart` instances (lost-by-reason, lost-by-stage) are **single-series** bar charts — each category lives on the x-axis, not encoded by a separate hue per bar. Per the project's dataviz method, a single-series magnitude chart takes the **sequential default hue (blue), not the 8-slot categorical palette** (categorical hues are reserved for multi-series identity, which doesn't apply here). Use:

| Chart element | Light | Dark |
|---|---|---|
| Bar fill | `#2a78d6` | `#3987e5` |
| Axis/gridline (hairline) | `#e1e0d9` | `#2c2c2a` |
| Axis tick / muted label text | `#898781` | `#898781` |
| Chart surface (Card background) | inherits `--card` token (already ~`#fcfcfb`-equivalent) | inherits `--card` token |

Do not introduce a rainbow/per-bar categorical palette for either chart — one hue, all bars, per the "sequential single-hue for magnitude" rule. If a future phase adds a second concurrent series to either chart, escalate to the categorical 8-slot palette starting at slot 2 (orange), never re-cycling slot 1.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 8 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | deal-table (per-group, list-collection) | ✅ covered | Search/filter that empties a group reuses that group's existing empty-state copy per CONTEXT.md D-04 (see Copywriting Contract row 2) — not a new message, and not distinguished from "genuinely empty." |
| empty | pipeline-board (all 6 groups hidden via visibility toggle, list-collection) | ✅ covered | Deselecting every group in the toggle shows the page-level "No pipeline stages selected." / "Choose at least one stage above to see deals." message (Copywriting Contract) instead of rendering a blank board with zero sections. |
| empty | lost-breakdown charts, both instances (list-collection) | ✅ covered | Zero lost deals renders the chart's empty-state copy (Copywriting Contract) in place of an axis with no bars — never a blank canvas. |
| empty | win-rate stat tile (static-content computed from a list) | ✅ covered | `won + lost === 0` renders "—" + "No closed deals yet" (Copywriting Contract) instead of "0%" or "NaN%" — directly closes RESEARCH.md Pitfall 5. |
| error | filter-controls: value-range, close-date-range (form) | ✅ covered | Invalid range shows inline validation copy (Copywriting Contract) below the control; the invalid filter is never silently applied as "matches nothing." |
| partial | filter-controls: value-range, close-date-range (form) | ✅ covered | A range filter with only one bound set (e.g. min filled, max blank) is treated as an open-ended bound (`>= min` or `<= max`) — not an error, not ignored. |
| zero-one-many | GroupSection header badge/total vs. filtered `DealTable` rows (list-collection) | ✅ covered | `GroupSection`'s count badge and $ total must recompute from the same filtered/sorted row set `DealTable` renders for that group — not the group's full pre-partition array — so the badge always reflects what's actually visible as search/filter narrows results. Flag for planner: this is a required wiring change, not cosmetic. |
| long-text | stat tiles: raw/weighted pipeline value (static-content) | ✅ covered | Values use `tabular-nums` and the existing whole-dollar `Intl.NumberFormat` (no decimals, unchanged formatter). A tile whose value would overflow wraps to a second line rather than clipping — 7-8 digit totals must stay fully legible. |
| overflow | lost-by-reason chart, many distinct categories (list-collection) | 🧪 backstop | If distinct `lostReason` categories exceed 6, fold everything ranked below the top 5 by count into a single "Other" bucket to keep the x-axis legible. Held-out test: seed 8+ distinct reason categories and confirm the chart renders ≤6 bars. |
| long-text | lost-by-reason chart, x-axis category tick labels (list-collection) | 🧪 backstop | Category tick labels longer than ~14 characters truncate with an ellipsis in the axis tick and show the full string in that bar's tooltip. Held-out test: seed a reason category whose text runs 40+ characters and confirm the tick truncates while the tooltip shows the full string. |
