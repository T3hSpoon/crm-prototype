# Requirements: iDrive CRM Prototype

**Defined:** 2026-09-15
**Core Value:** A working, demoable pipeline view — prospects flow through stages, lost deals are tracked with reasons, and won deals roll up as the contract list — solid enough to later wire into iDrive's existing project without a rebuild.

## v1 Requirements

Requirements for milestone v1.1. Each maps to roadmap phases.

### Pipeline

- [x] **DEAL-07**: User can edit a deal's confidence level inline from the pipeline table (not just at Add Deal creation)

### Forecast

- [x] **FCST-03**: User can view all deals (open, won, and lost) in a table on the Forecast page, grouped by confidence level, showing per-deal Account Name (company), Model (sku), Services (comma-joined service line-item names), Quantity (sum of service-type line-item units), ARPU (MRR / quantity), MRR, ARR, Lifetime Contract Value, and Contract Length (months)
- [x] **FCST-04**: User can see a subtotal row per confidence group and a grand-total row summarizing Quantity/MRR/ARR/Lifetime Contract Value across the whole table

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Analytics

- **ANLY-01**: Stalled-deal flag — surface deals that have sat in a stage longer than expected

### Integration

- **INTG-01**: Real API/database persistence, replacing the mock data layer
- **INTG-02**: Authentication and multi-user pipelines with ownership-based filtering

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| New `LineItem.model` field | Confirmed with user — the existing `sku` field fills the "Model" role for this milestone; no schema addition |
| Confidence-grouped table scoped to open deals only | User wants full visibility across the pipeline (open, won, and lost), not just the still-open scope the existing weighted-pipeline-value calculation uses |
| Kanban board view | Table-only for v1/v1.1 per PROJECT.md; a second view doubles UI surface with no backend to persist per-view state |
| Calendar / activity scheduling | Adds a whole new entity (activities/tasks) unrelated to core pipeline-tracking value |
| Authentication / multi-user / role-based permissions | Prototype is single-user and frontend-only; adds infrastructure with no payoff before a real backend exists |
| Backend/API persistence | Explicitly deferred until integration into the existing iDrive project |
