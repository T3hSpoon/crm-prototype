<objective>
**As a** salesperson editing pipeline deals and a sales manager reviewing the whole pipeline, **I want to** update a deal's confidence level right from the pipeline table and see every deal — open, won, and lost — broken down by confidence with subtotals, **so that** confidence stays current without reopening the Add Deal wizard, and I can size the full pipeline by how likely each slice actually is to close.

Task 1 (tracer) wires DEAL-07 end to end: a new shared confidence-level constants module, a widened store write-path, a new zod validation rule, a new `ConfidenceCell` component, and its column in `DealTable`. Task 2 (expansion) adds FCST-03's confidence-grouped breakdown table on the Forecast page (grouping, per-deal financial columns, mounted and visible). Task 3 (expansion) adds FCST-04's subtotal and grand-total rows on top of Task 2's table.

Purpose: closes out the v1.1 milestone — the last 3 requirements (DEAL-07, FCST-03, FCST-04) — building entirely on Phase 4's Forecast page and the pipeline table's existing click-to-edit conventions.
Output: an inline-editable Confidence column in the pipeline table, and a new always-visible confidence-grouped financial breakdown table (with per-group subtotals and one grand total) on the Forecast page.
</objective>

<assumption_delta_decision>
**Noun generalized:** confidence-level ordering/labeling. Before this phase it was implicit and single-purpose in two separate places — a module-private `CONFIDENCE_WEIGHT` map inside `forecast-metrics.ts` (used only for the Weighted Value calculation) and a locally-duplicated `CONFIDENCE_LEVEL_OPTIONS` array inside `AddDealDialog.tsx` (used only at deal-creation time). This phase introduces a shared, canonical `src/shared/constants/confidence-level.ts` (`CONFIDENCE_LEVELS` order + `CONFIDENCE_LEVEL_LABELS` labels) consumed by two independent NEW call sites: `ConfidenceCell` (editing) and `forecast-breakdown.ts`/`ForecastBreakdownTable.tsx` (grouping/display) — confidence grouping becomes a first-class, multi-consumer axis rather than an implicit, single-consumer weight multiplier.

**Decision:** `add-alongside`. The new shared constants module serves only this phase's 2 new consumers. `AddDealDialog.tsx`'s local `CONFIDENCE_LEVEL_OPTIONS` and `forecast-metrics.ts`'s private `CONFIDENCE_WEIGHT` are deliberately left untouched — CONTEXT.md's phase boundary explicitly excludes touching the Add Deal wizard's existing Confidence field, and `CONFIDENCE_WEIGHT` serves a different purpose (a weight multiplier, not an order/label map).

**What would force a later promote:** a future cleanup phase consolidating every confidence-level order/label definition (this phase's `confidence-level.ts`, `AddDealDialog.tsx`'s local options, `forecast-metrics.ts`'s `CONFIDENCE_WEIGHT` key order) into the one shared module, deleting the two now-redundant local definitions.
</assumption_delta_decision>
