> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present, detected not asked) |
| Preset | `b2fA` — style `radix-nova`, base color `neutral`, theme `neutral`, chart color `neutral`, radius `default`, menuAccent `subtle` (same preset Phase 4 confirmed via `npx shadcn info`; unchanged this phase) |
| Component library | radix (via shadcn) |
| Icon library | lucide-react (already a dependency; no new icon introduced this phase — Confidence cell and the breakdown table are text-only, matching `EditableCell`/`StageSelect`'s icon-free convention) |
| Font | Geist Variable (`@fontsource-variable/geist`), `font-sans`/`font-heading` both resolve to Geist — unchanged |

**Existing installed shadcn components used this phase:** `select` (already installed — reused as-is for `ConfidenceCell`, mirroring `StageSelect`'s existing usage). **No new shadcn component install required** — the breakdown table is a plain HTML `<table>` (RESEARCH.md's explicit recommendation: no sort/filter/expand needs, so TanStack Table buys nothing and a `card`/`badge` wrapper isn't required either — it follows `DealTable.tsx`'s existing plain-`<table>`-in-`overflow-x-auto`-div shell).

**Visual hierarchy (this phase's two surfaces):**
- **Pipeline table:** the new Confidence column sits among the existing editable columns (Name/Value/Owner/Close Date) — same visual weight as its siblings, no new emphasis. Recommended insertion point: immediately after Close Date, before the read-only Lifetime Contract Value column (keeps all 5 directly-editable fields contiguous; RESEARCH.md Open Question 2).
- **Forecast page:** the new confidence-grouped breakdown table is a new section mounted below the existing stat tiles + `LostBreakdownChart` grid (D-10) — it is the third visual tier on the page (tiles → charts → breakdown table), read top-to-bottom, not competing with the Display-size stat numbers for primary attention.

## Typography

Unchanged from Phase 4 — reuse the same 4 sizes / 2 weights, no new size or weight introduced:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`) | 600 (semibold) | 1.2 |
| Heading | 18px (`text-lg`) | 600 (semibold) | 1.2 |
| Display | 24px (`text-2xl`) | 600 (semibold) | 1.15 |

Usage mapping for this phase's new UI:
- **Body** (14px/400): all breakdown-table deal-row cell text (Account Name, Model, Services, Quantity, ARPU, MRR, ARR, Lifetime Contract Value, Contract Length) — matches `DealTable`'s existing row text exactly. `ConfidenceCell`'s display text ("100%" / "80%" / "50%" / "Open to RFP Bids") and its `Select` item text are also Body.
- **Label** (12px/600): confidence group section header text ("100%", "80%", "50%", "Open to RFP Bids" as group labels) and subtotal-row labels ("Subtotal — 100%", etc., built from the same label map).
- **Heading** (18px/600): none new this phase — the Forecast page's existing `<h1>Forecast</h1>` is unchanged.
- **Display** (24px/600): none new this phase — the existing stat tiles are untouched (out of phase boundary).

**Table header weight correction carried forward from Phase 4:** `DealTable`'s existing column headers use `font-medium` (500), flagged in `04-UI-SPEC.md` as a pre-existing, unaudited third weight that must NOT be extended to new components. The new breakdown table's column headers (Account Name/Model/Services/Quantity/ARPU/MRR/ARR/Lifetime Contract Value/Contract Length) use **Body size at 600 weight** (14px/600), not `font-medium` — stays within the project's 2-weight budget (400/600) while remaining visually close to the existing header row.

## Color

This project's theme is CSS-variable-driven (oklch, shadcn `neutral` base) — values below are the token, not a fixed hex, per `src/index.css`. Unchanged from Phase 4 — no new hue introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)`, white) | Page background, breakdown-table deal-row background (unchanged) |
| Secondary (30%) | `--card` / `--muted` (`oklch(0.97 0 0)`, near-white gray) | Breakdown table's column-header row background (`bg-muted/50`, matching `DealTable`'s `thead`), confidence-group header row background (`bg-muted/30`), subtotal-row background (`bg-muted/30`), grand-total row background (`bg-muted/50`, same weight as the column header to visually "bookend" the table) |
| Accent (10%) | `--primary` (`oklch(0.205 0 0)`, near-black in light mode) | Reserved for: `ConfidenceCell`'s `Select` trigger focus ring while in edit mode (identical `focus-visible:ring-ring/50` treatment already used by `EditableCell`'s `<input>` and `StageSelect`'s `SelectTrigger`) — no other new accent usage this phase. Confidence groups are **not** color-coded by hue (unlike pipeline stages' `GROUP_META` accent-bar system) — group identity is conveyed by the Label-weight text header only, per RESEARCH.md's "plain table" framing (no per-row color needs) |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)`, red) | Reused as-is for `ConfidenceCell`'s inline validation/update-failure text (same destructive-colored `text-xs` treatment `EditableCell` already uses) — no new destructive *action* exists this phase (confidence edits are non-destructive, instantly correctable) |

Accent reserved for: `ConfidenceCell`'s active-edit focus ring only. Never applied to confidence-group headers, subtotal rows, or the grand-total row — those use neutral `--muted`-family backgrounds plus weight (600) for emphasis, not color, consistent with the 10%-of-surface intent and with RESEARCH.md's explicit rejection of a new per-confidence-level palette.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None new this phase — DEAL-07's confidence edit is an inline click-to-edit cell (same interaction class as the existing Owner/Value/Close Date cells), not a button/CTA. The Forecast page remains read-only (Phase 4 D-03, unaffected) — the new breakdown table has no CTA. |
| Empty state heading | A confidence group with zero deals (D-09) renders its section header as normal (e.g. "50%") plus a body row reading **"No deals in this group yet."** — reuses `DealTable`'s exact existing empty-group copy verbatim (per D-09's explicit instruction to match that precedent), not a new string. |
| Empty state body | None beyond the heading above — matches `DealTable`'s existing empty-group row, which has no secondary body line either. |
| Error state | `ConfidenceCell` reuses the project's single shared update-failure string verbatim: **"Update failed — your change wasn't saved. Try again."** (`UPDATE_FAILED_MESSAGE`, `src/features/pipeline/constants.ts`) — same inline destructive-text-below-cell placement `EditableCell` already uses. No new error copy is introduced. |
| Destructive confirmation | None this phase — confidence-level changes are non-destructive and instantly reversible (re-selecting a different value); no confirmation dialog is introduced (mirrors Phase 4's precedent of no new destructive actions). |

**Confidence level display labels** (locked, sourced from `AddDealDialog.tsx`'s existing `CONFIDENCE_LEVEL_OPTIONS` — reuse verbatim, do not invent new label text):

| Value | Label |
|-------|-------|
| `"100"` | 100% |
| `"80"` | 80% |
| `"50"` | 50% |
| `"open-to-rfp"` | Open to RFP Bids |

**Breakdown table row labels (new this phase):**
- Subtotal row, Account Name column: **"Subtotal — {confidence label}"** (e.g. "Subtotal — 100%", "Subtotal — Open to RFP Bids").
- Grand-total row, Account Name column: **"Grand Total"**.
- Non-aggregatable columns on subtotal/grand-total rows (Model, Services, Contract Length, and ARPU if omitted per planner discretion) render **"—"**, matching the em-dash convention below — never a blank cell or a stray `0`.

**Em-dash conventions (locked by CONTEXT.md D-05/D-06/D-07 — reuse `EditableCell`'s existing missing-value convention, do not invent a new one):**
- Model / Services cell, deal with zero line items: **"—"**
- ARPU cell (per-deal, subtotal, or grand-total), Quantity = 0: **"—"** (never "$0" or a division error)

## UI Considerations

> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Probed elements: ConfidenceCell (interactive-control), confidence groups (list-collection), deal rows (list-collection), Model/Services cell (static-content), grand-total row (static-content). Applicable state considerations: 21 raised, 6 covered, 2 backstop, 13 dismissed (not applicable, reason required), 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | ConfidenceCell (interactive-control) | ✅ covered | Mirrors `EditableCell`'s `isPending` guard — while a commit is in flight, further clicks on the cell are ignored (`if (isPending) return;`); no spinner is introduced, matching the existing in-memory-write-is-effectively-instant precedent for Owner/Value/Close Date. |
| error | ConfidenceCell (interactive-control) | ✅ covered | `dealEditSchema.shape.confidenceLevel.safeParse` guards the value before `updateDeal`; a rejected/failed commit shows `UPDATE_FAILED_MESSAGE` inline below the cell (Copywriting Contract) and reverts to the last committed value — identical pattern to `EditableCell`. |
| long-text | ConfidenceCell (interactive-control) | ➖ dismissed | Confidence labels are a fixed, short enum (max "Open to RFP Bids", 17 chars) — never runtime-variable-length user content; no wrap/truncation handling needed. |
| empty | confidence groups (list-collection) | ✅ covered | D-09: a confidence group with zero deals still renders its header + an empty-state row reading "No deals in this group yet." (Copywriting Contract) — never hidden, never a blank section. |
| loading | confidence groups (list-collection) | 🧪 backstop | The breakdown table reads the same in-memory, synchronous `usePipelineStore((s) => s.deals)` array `ForecastPage` already reads for its stat tiles — no async fetch exists, so no loading skeleton is needed. Held-out test: confirm no loading/skeleton state is ever reachable in this phase (frontend-only, in-memory data — asserted, not merely assumed, per PROJECT.md's Phase 5 constraint). |
| error | confidence groups (list-collection) | ➖ dismissed | Pure synchronous derivation from in-memory store state (no async fetch/submit this phase) — no error state is reachable. |
| populated | confidence groups (list-collection) | ➖ dismissed | Row-level populated-state content is defined at the deal-row level below — no distinct group-level treatment beyond what that row specifies. |
| partial | confidence groups (list-collection) | ➖ dismissed | `Deal.confidenceLevel` is a required, always-populated field (set at creation) — every deal is deterministically assigned to exactly one group; no partial-membership state is reachable. |
| overflow | confidence groups (list-collection) | ✅ covered | Wrapped in the same `overflow-x-auto` horizontal-scroll div `DealTable` already uses (`<div className="overflow-x-auto rounded-lg border border-border"><table className="w-full min-w-max ...">`) — no column is hidden or collapsed at narrow widths. |
| zero-one-many | confidence groups (list-collection) | ✅ covered | Zero deals: handled by the empty-state row above. One or many deals: render as plain sequential rows with no pluralization-sensitive copy anywhere in this table (no "1 deal" / "N deals" count badge is required by FCST-03/04's plain column-list framing — a count badge is optional planner discretion, not a requirement). |
| empty | breakdown-table deal rows (list-collection) | ➖ dismissed | Same empty-state as the confidence-group list above — a group with zero deal rows shows the group's own empty-state row; there is no separate row-list empty state distinct from its parent group. |
| loading | breakdown-table deal rows (list-collection) | ➖ dismissed | Same synchronous in-memory data source as the confidence-group list above — no separate row-level loading state. |
| error | breakdown-table deal rows (list-collection) | ➖ dismissed | Same reasoning as the confidence-group list above — no async submit/load at the row level. |
| populated | breakdown-table deal rows (list-collection) | ✅ covered | Standard row rendering at Body size/weight, `px-4 py-2` cells, `border-t border-border` row dividers — pixel-identical to `DealTable`'s existing row treatment, at any typical row count (D-11: always expanded, no virtualization needed at prototype scale). |
| partial | breakdown-table deal rows (list-collection) | ➖ dismissed | Every column is a pure derived value computed from `Deal` + `LineItem[]` (both required, schema-validated structures) — no column can be missing while others compute for the same row; the one legitimate gap (zero line items) is the documented em-dash convention (Copywriting Contract), not a partial-row state. |
| overflow | breakdown-table deal rows (list-collection) | ➖ dismissed | Same `overflow-x-auto` shell as the confidence-group list above — no separate row-level overflow handling. |
| zero-one-many | breakdown-table deal rows (list-collection) | ➖ dismissed | Same zero/one/many behavior as the confidence-group list above (group-level) — no separate row-level treatment. |
| overflow | Model / Services cell content, comma-joined SKUs / service names (static-content) | ➖ dismissed | Same underlying behavior as long-text below — content wraps rather than clips or forces the table wider, so no separate overflow-specific handling exists. |
| long-text | Model / Services cell content, comma-joined SKUs / service names (static-content) | 🧪 backstop | A deal with many line items (5+) produces a long comma-joined string; the cell wraps onto a second line within its row rather than truncating with an ellipsis or forcing the table wider than its scroll shell — the full list is the column's purpose, so content is never hidden. Held-out test: seed a deal with 6+ line items and confirm the Model/Services cell wraps (not clips, not ellipsis-truncates) and the row's height grows to fit. |
| overflow | grand-total row (static-content) | ➖ dismissed | Grand-total row's cells are either aggregated numeric values (Quantity/MRR/ARR/Lifetime Contract Value) or the em-dash placeholder for non-aggregatable columns (Copywriting Contract) — never comma-joined/variable-length text, so no overflow risk exists on this row. |
| long-text | grand-total row (static-content) | ➖ dismissed | Same reasoning as overflow above — no variable-length text is ever rendered on the grand-total row. |
